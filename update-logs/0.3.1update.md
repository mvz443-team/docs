# 0.3.1 开发更新记录

本版本覆盖 `mvz443` 客户端从 `v0.2.2`（2026-05-12）起，以及 `mvz443-server` 服务端从 `v0.22.1`（2026-05-03）起，到 2026-11-22 的 main 分支累计变更。主线目标是**把联机从「能连上」推进到「可回滚、可重连、可复现」**，同时完成体态系统统一、第二章水路/飞行僵尸扩充、护盾植物与同格叠种体系、以及配套的确定性自查与调试工具。

> 说明：0.2.2 更新日志规划了「每周五预选版本」；仓库 main 分支没有对应的版本标签记录，因此 0.3.1 直接汇总这一阶段的全部主干提交，作为正式版前的最后一次大版本记录。

## 一、联机同步与确定性（客户端 + 服务端）

### 1.1 帧同步与权威落地

- [x] 完成预测式帧同步与可恢复回滚：本地操作只生成表现层虚影/HUD 预演，**不提前创建 Model 实体、不扣权威资源**；所有权威帧无条件落地一次，避免刷新重连后预测表为空导致漏操作。
- [x] 服务端帧窗口从 `current+4 ~ current+10` 收紧为 `current+2 ~ current+10`（`CommandLeadFrames=2`），降低操作延迟；超窗操作按确定性错误入帧并回传。
- [x] 服务端 loadout 规范化/去重排序 + FNV-1a 摘要，在 `AllReady` 广播；客户端用同一算法自检，摘要不一致直接阻止开局。
- [x] 双端投票与权威结束帧仲裁，结算结果不再由单端先到先得；重复投票幂等。
- [x] 客户端 `RequestBlank` 区分 `frameId`（心跳进度）、`ackFrameId`（补发起点）与 `hashFrameId`（摘要对应帧），避免污染 ACK 边界。
- [x] 卡顿与弱网处理：平滑追帧保护、伪帧对齐服务端权威帧号、极短帧间隔下的重复补发风暴修复。

### 1.2 状态哈希、Checkpoint 与回滚

- [x] 新增确定性状态收集、FNV-1a 32 位摘要与全量快照恢复核心；数值按 IEEE-754 位模式写入，避免 NaN / -0 / 键顺序差异。
- [x] 每 20 帧采样一次状态摘要，每 200 帧构造一次不含 Rapier physics 的 inline checkpoint；超过 6KB 自动退化为纯 hash。
- [x] 新增 `SnapshotRingBuffer`（每 10 帧记录、保留约 200 帧）与 `CombatManager.rollbackToFrame()`，支持 in-place 回滚后原帧重放。
- [x] Checkpoint 只在双端摘要一致时由服务端确认，并在 `ResponseReplayFrames` 中携带已确认的 inline 快照与从快照帧到当前帧的全部操作。
- [x] 分叉不再只告警：客户端进入不可恢复的离线单机模式，恢复暂停/倍速与正常收益，结算时导出一次 Desync 日志；服务端只记录“分叉已发生”，不修复分叉。

### 1.3 重连与房间生命周期

- [x] InGame 断线保留席位（`ReconnectGracePeriod=60s`），同 id 重连补帧；非 InGame 阶段重连重置准备/加载状态并补发房间配置。
- [x] 页面刷新后的完整恢复链路：`AllReady` 持久化 `room_id/chapter_id/stage_id` 与双方 loadout 用于重建 `GameParams`；服务端向延迟最低的在线玩家索取一次兜底快照（2 秒超时）并校验帧连续性后转发。
- [x] 每帧 blank 心跳上报 `energy/star_shards/card_cooldowns` 资源 profile，服务端按玩家保存并在重连 `AllReady` 回传；客户端等本地帧号追上 profile 帧号才套用，跳帧恢复时丢弃，避免重演期资源叠加。
- [x] 修复 `TileItemManager.RestoreTileItemState()` 把合法 wave 0 当缺省恢复成 -1 导致重连分叉的问题（改用 `Number.isFinite`）。
- [x] 对局中主动退出：`leave?destroy=1` 取消房间、广播对方离线、优雅排空发送队列后再关连接；结算后支持返回房间（`RequestReturnToLobby`），10 秒无操作兜底回大厅。
- [x] 新增玩家加载进度同步（单调递增、封顶 100、全员完成才开局）、房主鉴权/踢人/房间名与密码归一化、心跳超时（15s）清理静默断线。
- [x] 退房信号重试与房间名默认占位，减少“点了没反应”和空房间残留。

### 1.4 跨进程与跨局确定性

- [x] 实体随机流改为 `DeterministicRandom` 包装器，`state()` 可读写且引用稳定；PRNG 当前状态进入快照，重连后按 `worldSeed + salt + 稳定 SnapshotId` 重新播种。
- [x] 修复重连后随机流退化、回调 timer 句柄跨进程串线、召唤实体缺稳定身份三处分叉：`MobSpawnIdentity` 统一分配 `spawnSeq + mobSnapshotId`，`SIMULATION_STATE_VERSION` 升版。
- [x] 怪物死亡入账、Mutant 砸击伤害/恢复、僵尸清波计时改由 Model 的 `DeathSettle` / `Smash` 等 tickmanager 权威帧定时器驱动，不再依赖 Phaser 动画 `onComplete`。
- [x] 一次性表现事件进入 `logicEvents` 并按 `eventId` 去重；`lastConsumedEventId` 进入实体 `extra`，回滚重建不会重复消费。
- [x] 跨局清理：`ProjectileCmd.clearProjectiles()`、`managedTickManagers`、`logicEvents`、`TickerManager.timerFactories` 在 `Game.teardownSession()` 中显式重置，消除连续开第二局首帧分叉。
- [x] 卡槽冷却重构为基于权威帧推导（`cooldownEndFrame`），移除逐帧递减与快照依赖；profile/回放日志负责重建冷却状态。
- [x] 静态配置去快照化：植物 static 字段迁入非枚举 config + getter，怪物数值只读 `MonsterDefinition`，装备 def/key 进 config，仅运行时血量/破碎/挥动进快照。

### 1.5 调试与诊断

- [x] 新增服务端 `-netDebug` / `-netDebugDir`：记录每个用户命令的实际接收帧、改写后的执行帧、完整 payload、阶段流转、帧/ACK/连接快照；检测到分叉立即落盘 `.desync.json`，不等房间结束。
- [x] 客户端 `netDebug` 运行时开关（URL query / localStorage / 设置页）与 `window.MVZ_NET` 测试钩子；退出时导出 full-log，环形缓冲不丢最后权威 hash 与退出原因。
- [x] 新增性能采样器与 `DBG` 命令限制（仅本地单机）、`DBG.downloadLogs()`；`isDebug` 设置项更名为 `basicDebug`，保留 cookie 兼容。
- [x] 新增无渲染确定性模型测试、双窗口 E2E、刷新重连 E2E、暂停退出 E2E，以及 `sim-debug` 多会话压测（最近一次 54/54 通过）。

## 二、体态系统与命中判定（统一化）

- [x] `LogicModel` 新增 `tiny / flying / inVoid` 三个普通布尔字段，自动进入快照与哈希；`BodyTraits.canReachBody()` / `readBodyLayers()` 是唯一命中判定入口。
- [x] 投射物用 `canHit(target)` 取代散落的 `skipTiny / couldAttackFlying`；新增 `hitKind`（`bullet` / `laser` / `explosion`）供载具/护甲区分伤害来源。
- [x] 植物射击判定线用 `SightLineOptions.reach` 与投射物共用体态规则；僵尸普攻用 `MonsterModel.canStartAttack()`；移除 `CombatEntity.isTiny` / `PlantModel.isTiny` 等分散字段。
- [x] 同格穿透遵守体态规则，气球僵尸按旋转后的躯体中心对齐。

## 三、植物与种植体系

- [x] 新增 **pid 18 蹦蹦铁砧**：地面器械，星碎/攻击/冷却按 preset 描述实现并补齐测试。
- [x] 新增 **pid 19 南瓜护照**：2500 血、125 能量、低矮护盾植物、不攻击；星碎回满血并进入尖刺状态（近战伤害返还一半）；同格内部植物由护盾优先承担伤害（`PlantModel.redirectDamageToShield()`）。
- [x] 南瓜护照 10 帧分层渲染（后壁/前壁 × 普通/破损/尖刺），血量降到 50% 显示破损；护盾破碎后僵尸在同格接力目标并通过 `attackTargetRank` 显式全序选目标，不依赖 `PlantsMap` 插入顺序。
- [x] 星之碎片/铲子悬浮高亮改为按目标精灵轮廓加色，取消整格方框；预览与执行共用 `PlantHelper.GetStarShardsTarget` / `GetRemovePlantTarget`，做到所见即所得。
- [x] 新增 **pid 20 气球TNT**：450 血、125 能量、14 秒冷却、低矮；6 秒充气升空（Lv5 起 3 秒），充满后只被飞行怪引爆，3x3 爆炸 350 伤害（Lv9 400）。
- [x] 气球TNT 星碎：立即充满并召唤 mid 21 气球TNT分身（PLANT 阵营飞行单位，200 血），向右飞行接触首个僵尸或到右边界爆炸。
- [x] 新增 `PlantModel.allowedPlantSlots`（`ground/water/sky` 白名单），TNT 地雷限制为仅地面，不能种在水面/睡莲上；解耦种植白名单与 `carrier/shield/normal` 叠种三态属性。
- [x] 新增 `placementRule / stackRole / requiredBasePid / isOneTimePlant`；高级植物替换基座统一走 `PlantHelper.CreateEntityWithBaseReplacement()`，先创建新植物再销毁指定基座并继承睡眠状态；同格睡莲/护盾不受影响。
- [x] 接触判定改为碰撞事件驱动：气球TNT / TNT 地雷删除每帧轮询，改为 `onCollision` + 状态切换瞬间一次性补判（`checkAirborneCollisionOnce` / `checkContactOnce`）。
- [x] 手杖僵尸改为“中心沿移动方向 0.7 格判定线”起跳，固定飞 1.4 格，落地按 `GetPlantsInGrid` 补判。
- [x] 植物静态字段封进非枚举 config；`inBruteShoot` 等表现状态改为 Model 字段并进快照，`syncViewFromModel()` 恢复头部姿态。

- [x] 新增 mid 21 气球TNT分身（PLANT 阵营），接触判定与边界触发按移动方向最后一格计算，不再硬编码最右列半格。
- [x] 新增 5 种木船僵尸（mid 22-26）：木船坐骑 400 血、`mountDamagePriority="rider"`、`habitats=["water"]`；坐骑被打碎后骑手在水中会溺亡。
- [x] 新增 mid 27 潜水僵尸：Model 内切换 `tiny`（潜行为 true、攻击探出为 false），面罩/波纹效果与头部挂点同步；新增 tiny 雪球命中链路。
- [x] 新增 mid 28 海豚骑乘僵尸：海豚坐骑 250 血、`mountDamagePriority="mount"`（坐骑先扣血），破碎后速度回退普通僵尸；放大海豚图层并补形态截图脚本。
- [x] 统一坐骑伤害路由：`MonsterModel.absorbMountDamage()` 按 `explosion/mount/rider` 与 `hitKind` 决定吸收顺序；新增环境溺亡 `applyMonsterDrowning()`（非水行、坐骑破碎后每帧扣 5% 最大生命）。
- [x] 攻击伤害拆分：`baseAttackDamage`（空手近战）+ 主手 `weaponDamage`；`EquipmentDef` 用 `weaponDamage` 取代 `damageLossOnBreak`，装备耐久消耗由 Model 决定。
- [x] 统一 buff/debuff 系统：`Buffs.ts` 定义 `slow/frozen/berserk` 与到期事件，状态全在 Model（三个到期帧字段进快照），`CombatEntity` 提供 `addDebuff/removeDebuff/hasDebuff/clearAllDebuffs` 委托；黑曜石傀儡/监守者/蜈蚣免疫，冰冻到期链缓慢。
- [x] 龟壳弓手破壳 buff 增加防重复并立即同步移动速度。
- [x] 僵尸普攻目标选择改为 `attackTargetRank` 显式全序（护盾 0 > 粉尘 1 > 普通植物 2 > 承载物 3，同级按 pid/SnapshotId 兜底）；目标销毁后由 Model 在同格接力，不重建攻击定时器，普攻循环按事件名 `removeByEvent("MonsterAttack")` 兜底清理。
- [x] 引入地形通行域：`TerrainHabitat.dominantHabitat()` 按水面/sky 占比（严格 > 0.5）过滤刷怪行，飞行怪无视限制；早期 3 波仍避开水道。
- [x] 蜈蚣冲锋/弧形换位改由 `ChargeImpact` / `RepositionDone` 等 tick 事件结算，Tween 只播放表现，权威坐标不写在动画回调里。
